Tab activity — the four states
One glyph per tab, in a fixed 14px slot at the right of the row. Shape carries the state as well as colour, so it survives a recoloured accent and a colour-blind glance. The slot is always present, so nothing reflows when a state changes.
Running Bytes arrived in the last 2 seconds. Green #2fd6a3, filled. Derived in pane.ts's single output callback — stamp lastOutput = Date.now() there and nothing else changes. A 1 s timer re-derives the rail, so a tab decays to idle on its own.
Idle Quiet, alive, presumably at a prompt. A hollow ring in --faint. This is the resting state of most tabs, so it must be the quietest mark on the row — an outline, not a fill.
Waiting A bell rang while you were somewhere else. Accent triangle, pointing up. Cleared the moment you focus the tab. This is the one state that should draw the eye: it is Claude Code asking for permission, or a long build finishing. Claude Code only rings when preferredNotifChannel is terminal_bell — Settings says so next to the toggle.
Exited The shell ended with a non-zero code. A red cross, and the row's subtitle becomes exited · code N at 72% opacity. Clean exits close the tab as they do today; only failures leave a mark.
Rules
One per tab A tab with four panes shows the loudest state among them: waiting > exited > running > idle. The pane-count badge already says there is more than one; the dot says whether any of them wants you.
Collapsed groups A folded project rolls its tabs up into the header: the states present, deduplicated, at 5px. A collapsed project can hide a waiting tab today — this is the fix.
The rail header Counts what is waiting across everything, in the accent: 2 waiting. Absent when the count is zero — no "0 waiting" chrome.
No animation Nothing pulses, nothing blinks. A dozen sessions means a dozen potential blinkers in peripheral vision for hours. State changes cross-fade over 120 ms and stop. (The capture dot's existing pulse is the one exception, and it slows to a 3 s breath.)
Reconcile, don't rebuild The rail currently does replaceChildren() on every title and cwd report. Adding a per-second state pass on top of that would rebuild ~30 rows a second. The dot lands together with keying rows by tab id and patching in place.
Not in this feature
No OS notifications. A toast from the taskbar for a terminal you are already looking at is noise. If it is wanted later it belongs behind a per-project toggle, not here.
No output preview. The last line of a pane in the rail row is tempting and wrong: it makes every row a moving target and doubles the repaint cost.
No "busy" spinner. Output activity is not progress. A spinner would claim to know something the terminal cannot know.
